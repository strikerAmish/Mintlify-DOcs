1. Executive Summary & System Architecture
PiyAPI is an enterprise-grade cognitive memory engine engineered for AI-native applications, intelligent agents, and
enterprise workflows. It provides LLMs with a persistent, long-term bitemporal memory fabric, multi-signal hybrid
search, dynamic context window assembly, knowledge graph reasoning (PiyGraph), active inference (Friston Free
Energy Principle framework), and privacy-first data handling.

Key Technical Subsystems
1. Hybrid Retrieval Pipeline: Combines dense vector similarity (pgvector  HNSW indexes) and BM25 trigram
full-text search fused using Reciprocal Rank Fusion (RRF_K=30 ).
2. UnifiedScorer Engine: Evaluates 11 signals in a single functional pass (vector similarity, BM25 text score,
recency decay, entity overlap, contradiction penalty, assistant boost, pin weight, etc.).
3. 8-Operator Memory Surface: Standardized lifecycle operators (store , retrieve , update , delete ,
merge , summarize , pin , verify ).
4. PiyGraph Knowledge Graph: Bitemporal entity-relation graph tracking real-world validity (valid_at )
separately from system recording time (system_at ).
5. BYOK (Bring Your Own Key): Encrypted multi-provider LLM key manager supporting OpenAI, Anthropic,
Google Gemini, DeepSeek, Mistral, Groq, Cohere, and Perplexity.
6. 12 SaaS CDC Data Connectors: Continuous Change Data Capture ingestion engine for Google Drive, Notion,
GitHub, Slack, Jira/Confluence, Gmail/Calendar, Web Clipper, ChatGPT, Claude, Gemini, Obsidian, and
OpenClaw.
7. White-Labeled Partner B2B API: Multi-tenant provisioner for SaaS vendors to manage sub-accounts and set
per-user rate limit caps.
8. Admin Control Suite: Full platform administration suite for user management, support impersonation, plan
overrides, cache flushing, business metrics, and AI model routing.

2. 5-Minute Client Quickstart Guide
Get up and running with PiyAPI in 5 minutes using simple HTTP cURL calls or client SDKs.
Step 1: Create an Account & Acquire API Key
curl -X POST https://api.piyapi.cloud/api/v1/auth/register \
  -H "Content-Type: application/json" \
  -d '{
    "email": "developer@example.com",
    "password": "StrongPassword123!",
    "name": "Alex Developer"
  }'
Step 2: Store Your First Memory
curl -X POST https://api.piyapi.cloud/api/v1/memories \
  -H "Authorization: Bearer YOUR API KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "content": "User prefers dark mode UI and works primarily with React and TypeScript.",
    "tags": ["preferences", "tech-stack"],
    "metadata": { "source": "onboarding_chat", "user_id": "usr_9918" }
  }'
Step 3: Perform Hybrid Search
curl -X POST https://api.piyapi.cloud/api/v1/search \
  -H "Authorization: Bearer YOUR API KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "query": "What frontend framework does the user prefer?",
    "limit": 5,
    "include_metadata": true
  }'
Step 4: Ask RAG Engine with Citations
curl -X POST https://api.piyapi.cloud/api/v1/ask \
  -H "Authorization: Bearer YOUR API KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "query": "Summarize the user code preferences and UI choice.",
    "temperature": 0.2
  }'

3. Authentication & Namespace Scoping
PiyAPI supports three client authentication modes and enterprise tenant isolation.
3.1 Authentication Headers
Mode A: JWT Bearer Token (User Sessions & Web Dashboards)
Authorization: Bearer eyJhbGciOiJIUzI1NiIsIn...
Mode B: API Keys (Backend Microservices & Agent Tools)
Passed via Authorization: Bearer  or X-API-Key :
Authorization: Bearer YOUR API KEY
Mode C: BYOK Direct Routing Header (Optional)
X-BYOK-Provider: openai
3.2 Key Verification Endpoint (GET /api/v1/verify ) — Live Verified
Clients can test API key validity:
curl -s https://api.piyapi.cloud/api/v1/verify \
  -H "Authorization: Bearer YOUR API KEY"
# Response: {"status":"valid","key_id":"...","scopes":["memory:read","memory:write"]}
3.3 Enterprise Namespace Isolation (X-Namespace-Prefix )
X-Namespace-Prefix: proj_acme_prod
When set, memory queries, knowledge graph traversals, and search indices will be strictly filtered to records
matching this namespace prefix.

  apiKey:
    process.env.PIYAPI_API_KEY ||
    'YOUR API KEY',

import crypto from 'crypto';
function verifyWebhookSignature(rawBody: string, signatureHeader: string, secret: string): boolean {
  const parts = signatureHeader.split(',');
  const timestamp = parts.find((p) => p.startsWith('t='))?.split('=')[1];
  const signature = parts.find((p) => p.startsWith('v1='))?.split('=')[1];
  if (!timestamp || !signature) return false;
  const payload = `${timestamp}.${rawBody}`;
  const expectedSignature = crypto.createHmac('sha256', secret).update(payload).digest('hex');
  return crypto.timingSafeEqual(Buffer.from(signature), Buffer.from(expectedSignature));
}
Python Verification Code:
import hmac
import hashlib
def verify_webhook_signature(raw_body: str, signature_header: str, secret: str) -> bool:
    parts = dict(item.split('=') for item in signature_header.split(','))
    timestamp = parts.get('t')
    signature = parts.get('v1')
    if not timestamp or not signature:
        return False
    payload = f"{timestamp}.{raw_body}".encode('utf-8')
    expected = hmac.new(secret.encode('utf-8'), payload, hashlib.sha256).hexdigest()
    return hmac.compare_digest(signature, expected)
