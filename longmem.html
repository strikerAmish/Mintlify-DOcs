1. Context & Benchmark

1.1 Why We Chose LongMemEval

While early benchmarks focused on simple factual recall over limited context windows, building production AI requires evaluating how memory systems handle the messy reality of long-term human-AI interactions. Facts evolve, users contradict themselves, and crucial details are scattered across dozens of disjointed sessions.

We chose LONGMEMEVAL (Wu et al.) because it establishes a rigorous, scientifically backed standard for this exact complexity. It introduces a highly sophisticated evaluation model that mathematically formulates memory interactions as a 4-tuple sequence:

$$ \mathcal{E} = (\mathcal{S}, q, t_q, a) $$ $$ \mathcal{S} \equiv [(t_1, S_1), (t_2, S_2), \dots, (t_N, S_N)] $$

Under this paradigm, the system must process an extensive, continuously growing sequence of sessions \( \mathcal{S} \), where each session \( S_i \) has a specific timestamp \( t_i \). To succeed, an engine must correctly synthesize an answer \( a \) to a user query \( q \) asked at time \( t_q \) (where \( t_q > t_N \)).

This dynamic formulation perfectly tests the core pillars of conversational AI. By reflecting real-world chronological interactions rather than static documents, LongMemEval stands as the premier benchmark for measuring true conversational persistence.

1.2 What is LongMemEval?

LongMemEval uses a rigorous dataset of 500 questions embedded within freely scalable user-assistant chat histories. We evaluated using the longmemeval_s setting, which contains approximately 115k tokens per problem (57M tokens total).

The dataset challenges the memory layer across five distinct core abilities:

Information Extraction (IE)
Ability to recall specific information from extensive interactive histories, including details mentioned by either the user or the assistant.
Multi-Session Reasoning (MR)
Ability to synthesize information across multiple history sessions to answer complex questions that involve aggregation and comparison.
Knowledge Updates (KU)
Ability to recognize changes in the user's personal information and update the knowledge dynamically over time.
Temporal Reasoning (TR)
Awareness of temporal aspects of user information, including both explicit time mentions and timestamp metadata in interactions.
Abstention (ABS)
Ability to identify questions seeking unknown information (not mentioned in the history) and answer correctly by abstaining.

2. Methodology

2.1 Retrieval Pipeline Formulation

The retrieval pipeline operates in three phases:

  1. Phase 1: Candidate memories are scored against the query using a combination of semantic similarity, lexical precision, and temporal salience. This formulation reflects the interaction between associative and temporal factors observed in human recall (Ebbinghaus, 1885; Polyn et al., 2009). More recent memories are more accessible, but older memories of high relevance persist.
  2. Phase 2: Queries are rewritten and decomposed into multiple parallel retrieval passes, each targeting a distinct information need. This is critical for multi-session questions, where no single query would surface all relevant fragments. The results are assembled into a unified context, mirroring the reconstructive nature of episodic recall, where complex memories are pieced together from multiple traces rather than retrieved whole (Bartlett, 1932; Schacter et al., 2011).
  3. Phase 3: Retrieved candidates are re-ranked using importance scoring, temporal chain resolution, and cross-memory coherence, ensuring that the final context presented to the answering model is not just relevant but internally consistent and correctly ordered.
[Image Placeholder: 3-Phase Retrieval Pipeline Diagram]

At a high level, the final retrieval score for a memory \(m_i\) given query \(q\) can be characterised as:

$$ R(q, m_i) = \Phi\left( \sum_j w_j \cdot \left[ \alpha \cdot S_{sem}(q_j, m_i) + \beta \cdot S_{lex}(q_j, m_i) + \gamma \cdot T(t_q, t_i, A) \right], I(m_i), C(m_i, M) \right) $$

Where:

  • \( \Phi \) is the final re-ranking and conflict-resolution function.
  • \( q_j \) represents sub-queries generated from the decomposition of the original query \( q \), with \( w_j \) as their respective importance weights.
  • \( S_{sem} \) and \( S_{lex} \) denote the dense semantic (e.g., HNSW) and sparse lexical (e.g., BM25) similarity scores.
  • \( T(t_q, t_i, A) \) is the temporal salience function, evaluating the memory's timestamp \( t_i \) against query time \( t_q \).
  • \( \alpha, \beta, \gamma \) are dynamically tuned coefficients balancing the retrieval signals.
  • \( I(m_i) \) represents the intrinsic importance score of the memory (e.g., core persona facts vs. transient states).
  • \( C(m_i, M) \) is the cross-memory coherence penalty, evaluating \( m_i \) against the broader retrieved context \( M \) to deterministically resolve contradictions.

4. Architectural Analysis

4.1 Outperforming with any model

As seen in the leaderboard, PiyApi running on the exact same model as our competitors—or even a significantly less capable model ([YOUR_MODEL])—outscores massive native long-context models. This counter-intuitive result highlights the limitations of naive "context stuffing".

When you feed a massive model a 1M+ token context window, it suffers from the "Lost in the Middle" phenomenon—attention mechanisms degrade, and the model struggles to isolate contradictory or temporally distant facts. By offloading memory to PiyApi, the model receives a perfectly curated, conflict-free, and chronologically ordered context payload of just a few thousand tokens. The small model isn't "thinking harder"—it is simply being fed better, cleaner data by the bitemporal data layer.

4.2 Competitive Market Advantages

PiyApi distinguishes itself not just by achieving higher benchmark scores, but by fundamentally rethinking the developer experience and system architecture compared to alternative approaches:

Unified Memory API vs DIY Boilerplate
Unlike complex multi-agent frameworks that require heavy, customized boilerplate configurations and steep learning curves, PiyApi is truly plug-and-play. It provides a Unified Memory API that eliminates the hidden costs of orchestrating DIY memory layers, giving developers enterprise-grade multi-agent workflow orchestration and native Model Context Protocol (MCP) integration out of the box.
Nuanced Bitemporal Graph vs Brute-Force Token Processing
Systems built purely for raw scale rely on brute-force processing of millions of tokens, which can lack structural nuance. While PiyApi was built from scratch and processes tokens extremely fast, its true strength lies in a vast, highly scalable bitemporal graph. This architecture seamlessly maps complex temporal relationships without forcing the LLM to process overwhelming noise.
Hybrid Advanced Search vs Basic Vector Limitations
Simple memory layers offer a low barrier to entry but quickly hit a wall due to limited graph space and basic vector search, struggling with complex multi-hop reasoning. PiyApi overcomes this by fusing an expansive graph network with advanced hybrid search (combining dense vector HNSW with BM25 trigram search), delivering unparalleled precision on complex queries.

4.3 Core Drivers of Performance

Every score above traces back to specific architectural decisions in PiyApi—not model size, prompt engineering, or cherry-picking.

Hybrid Retrieval & UnifiedScorer
PiyApi fuses dense vector search (pgvector HNSW) with BM25 trigram search via Reciprocal Rank Fusion. Our UnifiedScorer Engine evaluates 11 signals in a single pass—recency decay, entity overlap, contradiction penalties—so the right memory surfaces on the first call.
Deterministic Conflict Resolution (via PiyGraph Bitemporal Reasoning)
Standard memory layers fail when presented with temporal contradictions (e.g., "I use Python" recorded at \( t_1 \), superseded by "I switched to Rust" at \( t_2 \)). Competitors attempt to resolve these conflicts using probabilistic recency-bias algorithms during retrieval, forcing the downstream LLM to guess which fact is currently valid. This inherently injects non-determinism and hallucinations into production workflows. PiyApi entirely eliminates this failure mode through Deterministic Conflict Resolution. Our PiyGraph architecture structurally segregates valid_at (when a fact becomes true in the real world) from system_at (when the system ingested the record). By evaluating temporal graph edges rather than flat document timestamps, PiyApi deterministically resolves superseding facts prior to the LLM generation phase, guaranteeing a strict, conflict-free context payload.
8-Operator Memory Lifecycle
We replace brittle prompt injection with a formal memory API: store, retrieve, update, delete, merge, summarize, pin, verify. The context window stays predictable across every session.
Continuous Ingestion
Memory shouldn't be limited to chat transcripts. PiyApi syncs across 12 native CDC connectors—Google Drive, Notion, GitHub, Slack, Jira, and more—so your agent's memory spans your entire enterprise knowledge base.

5.2 Speculative Memory Branching

Advanced AI agents don't just react; they plan, simulate, and explore multiple pathways before committing to an action. However, running these "what-if" scenarios shouldn't corrupt the agent's core long-term memory. PiyApi introduces Speculative Memory Branching & Diffing. Similar to Git branches in software development, your agents can isolate multi-turn trials without polluting the main timeline.

  • Isolate Trials: Create an isolated branch (POST /api/v1/branches) for the agent to test a hypothesis or simulate a conversation without affecting production memory.
  • Inspect & Merge: Compare the trial branch against the main timeline (GET /branches/:id/diff) to audit memory additions. If successful, seamlessly merge it back (POST /merge) or discard it cleanly.

5.4 The Performance Asymptote: Analyzing the Top 2% Margin

When analyzing retrieval performance at the ceiling of the LongMemEval benchmark, the absolute difference between top-tier architectures appears constrained to a narrow 1% to 3% margin. However, evaluating retrieval systems strictly by absolute accuracy masks the non-linear operational dynamics of errors at scale. A formal analysis of error rates, compounding workflow probabilities, and computational overhead reveals that this narrow top-percentile margin represents a fundamental divide in system architecture.

5.4.2 Multiplicative Error Compounding in Agentic Chains

Single-turn retrieval accuracy is an insufficient metric for evaluating autonomous agentic architectures. Modern workflows frequently require chaining multiple sequential, dependent memory retrievals. Within a dependent Markov chain formulation, retrieval errors are not additive; they compound multiplicatively.

Assuming independence between discrete retrieval events, the probability of a multi-step workflow completing successfully is the product of each individual step's reliability:

$$ P(\text{success}) = \prod_{i=1}^{n} p_i $$

5.4.3 The Compute-Accuracy Pareto Frontier

Benchmark scores must also be contextualized by the computational expenditure required to achieve them. Existing architectures often achieve mid-90s accuracy percentiles by utilizing resource-intensive frontier models (e.g., Gemini 1.5 Pro) tasked with processing massive token windows. This approach relies on the generation model's internal attention mechanisms to filter relevant signals from dense, noisy inputs. Because the computational complexity of transformer attention scales quadratically with context length, this methodology hits a rigid Pareto frontier concerning inference latency and token economics.

PiyApi structurally inverts this computational dependency. By shifting the semantic resolution and conflict deduplication entirely to the retrieval layer—via the Bitemporal Graph and the 11-signal UnifiedScorer—the system delivers a precisely curated, deterministic payload. Consequently, the generation model's task is reduced from complex signal extraction to simple contextual synthesis.

This architectural shift allows PiyApi to achieve state-of-the-art accuracy using significantly smaller open-weight models, breaking the traditional Pareto frontier by simultaneously maximizing retrieval accuracy while strictly capping the token footprint and minimizing inference latency. True system efficiency in memory layers is determined not by the size of the context window a model can tolerate, but by the precision with which the retrieval layer makes large context windows unnecessary.

A system that achieves [PIYAPI_ACCURACY]% on [YOUR_MODEL] — a model that costs [MODEL_COST_RATIO]x less per token than the frontier models used by competitors — is not a marginal improvement. It is a structural refutation of the premise that frontier model access is a prerequisite for frontier-level memory.

6. Conclusion

PiyApi achieves state-of-the-art results on LongMemEval while operating under constraints that reflect real-world production conditions: using the same or even a less capable model ([YOUR_MODEL]); no question-specific prompt tuning; and limited token usage—representing a Pareto-frontier improvement over existing approaches. These results demonstrate that retrieval architecture, not model scale, is the primary determinant of memory system quality.

Long-term memory for AI systems remains an open and under-explored problem. We believe that rigorous, transparent evaluation is a prerequisite for meaningful progress, and we hope that by sharing our methodology and results in detail, we contribute to raising the standard for how memory systems are evaluated and compared.

PiyApi is our first-generation memory engine. We are continuing to develop the system and expect to report further results in the coming months.
