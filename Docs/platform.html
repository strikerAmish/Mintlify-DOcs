Platform Overview

Everything you need to build, manage, and scale persistent intelligence with PiyAPI.

Production Architecture
•
Updated recently

PiyAPI provides the infrastructure for persistent intelligence across AI applications.

The platform manages memory, context, and retrieval as distinct layers, allowing applications to store relevant information and recall it precisely when needed rather than relying on ephemeral session state.

This document introduces the core building blocks of PiyAPI and describes how they compose into a working system for AI agents and applications.

How PiyAPI Works

The five-stage pipeline transforms raw multi-turn dialogue into high-signal context vectors with bitemporal validity. Styled in an alternating lavender and white architecture:

01
Capture & Ingest CDC CONNECTORS
Conversational or event data enters the system via API, SDK, or one of 12 native CDC connectors (Google Drive, Notion, GitHub, Slack, Jira, Gmail, and more). Automatic chunking and tokenization preserve private identifiers.
02
Store & Bitemporal Index PGVECTOR HNSW
Relevant facts are persisted in PostgreSQL with pgvector HNSW indexing. Every record is stamped with valid-time (valid_at) and transaction recording time (system_at) for zero-loss auditability.
03
Multi-Signal Retrieval UNIFIEDSCORER
The UnifiedScorer evaluates 11 signals in a single pass — combining dense vector similarity, BM25 trigram full-text search, recency decay, entity overlap, contradiction penalty, and pinned memory weights with calibrated RRF_K=30.
04
Compose Context Payload TOKEN BUDGET
Retrieved memory is dynamically assembled into a token-budget-aware context payload via POST /api/v1/context/retrieve. Redundant facts are compressed to preserve model context windows.
05
Generate & Self-Learn BYOK ROUTING
Context is injected into the system prompt for inference. Native BYOK encryption lets you route requests directly to OpenAI, Anthropic, Gemini, or DeepSeek while session mining captures user feedback.
Pipeline Stage Underlying Subsystem & Protocols
01 01 Capture WebSocket Ingestion, 12 CDC Connectors, Webhooks, @piyapi/sdk
02 02 Store (Lavender) PostgreSQL 16 + pgvector, Bitemporal Graph, AES-256-GCM Envelope Encryption
03 03 Retrieve UnifiedScorer (11 Signals), HNSW Cosine Similarity, BM25 Full-Text, Reciprocal Rank Fusion
04 04 Compose (Lavender) Context Assembly Engine, Token Pruning, Deduplication Filter, POST /api/v1/context/retrieve
05 05 Generate BYOK Multi-Provider Router, Model Inference, Adaptive Feedback Mining (/api/v1/feedback)

5-Minute Client Quickstart

Integrate persistent bitemporal memory into your agents and LLM applications in under five minutes.

Developer Onboarding
•
5 min setup • Live Endpoints

PiyAPI decouples cognitive memory from stateless LLM inference. Follow the four-step setup pipeline below to store durable user preferences and recall them in real-time:

01
Install Official SDK or Connect via REST INGRESS PROTOCOL
Install the lightweight, production-hardened client for Node.js/TypeScript or Python with native streaming and auto-reconnecting WebSocket support.
02
Authenticate with Workspace API Key AUTH & BYOK
Initialize the client using your live API key (sk_live_...). Optionally attach BYOK headers (OpenAI, Anthropic, Gemini, DeepSeek) to route inference directly through your enterprise accounts.
03
Persist Bitemporal Memory Facts O(1) MEMORY STORE
Store conversational statements, entity attributes, or structured metadata. PiyAPI automatically computes 1536-dim vector embeddings and stamps bitemporal intervals (valid_at vs system_at).
04
Retrieve Context & Complete Model Prompts HYBRID RECALL
Query memory via client.search() or dynamic context assembly via POST /api/v1/context/retrieve with token-budget enforcement and automatic PHI/PII redaction.

Step 1 • Installation

Choose between our official TypeScript library or Python package. Both clients feature automatic token-budget management, connection pooling, and resilient retry logic:

terminal 
# Install TypeScript SDK
npm install @piyapi/sdk

# Or install Python SDK
pip install piyapi-memory

Step 2 • Initialize Client & Retrieve Context

Authenticate your client and execute an end-to-end memory store and contextual recall in a single script:

quickstart.ts 
import { PiyAPIClient } from '@piyapi/sdk';

const client = new PiyAPIClient({
  apiKey: process.env.PIYAPI_API_KEY || 'sk_live_...',
  namespace: 'enterprise_workspace_prod'
});

// 1. Store persistent fact
await client.memories.create({
  content: "User requested quarterly forecast in EUR currency with dark mode theme",
  tags: ["preferences", "finance"],
  metadata: { user_id: "usr_9918", session_id: "sess_441" }
});

// 2. Retrieve assembled context
const context = await client.context.retrieve({
  query: "What currency should we render the charts in?",
  user_id: "usr_9918",
  token_budget: 1500
});

console.log('Assembled Context:', context.rendered_prompt);
💡
Enterprise Tip: For high-throughput environments, set the X-Namespace-Prefix header to isolate multi-tenant customer records at the database partition layer.

Platform / Memory

Persistent Memory & 8-Operator Surface

Durable, bitemporal fact storage governed by an atomic eight-operator cognitive surface.

Memory Substrate
•
Unified 8-Operator Surface • Bitemporal

Persistent memory provides durable state retention across multiple conversational turns, user sessions, and AI agents. Explore the core architectural pillars below:

01
Unified 8-Operator Memory Surface ATOMIC ENGINE
A unified interface exposing store, retrieve, update, delete, merge, summarize, pin, and verify for fine-grained cognitive control.
02
Bitemporal Validity Tracking TIME TRAVEL
Every memory record independently stores valid_at (when the event occurred in the real world) and system_at (when it was logged in the database) to eliminate factual drift.
03
Speculative Memory Branching WHAT-IF SIMULATION
Branch off memory graphs into isolated sandbox environments using POST /api/v1/branches, simulate agent actions, and merge diffs back to main after user approval.
04
Pinned Memory Guarantees ZERO DECAY
Mark critical compliance rules, user constraints, and security policies as pinned to bypass recency decay curves and guarantee 100% prompt recall.

The Unified 8-Operator Surface

All mutations on persistent memory execute through eight standardized atomic operators:

store()
Insert new facts with embeddings & bitemporal timestamps.
retrieve()
Fetch context vectors via 11-signal UnifiedScorer.
update()
Patch fact content while maintaining historical audit trail.
delete()
Cryptographic shredding & soft-delete compliance flags.
merge()
Synthesize multiple redundant memories into unified knowledge.
summarize()
Generate loss-less semantic summaries for long conversation threads.
pin()
Lock high-priority rules with infinite recency half-life.
verify()
Cross-validate fact coherence against knowledge graph edges.

Python SDK Memory Implementation

Execute atomic memory operations using the official Python client:

memory_operations.py 
from piyapi_memory import PiyAPIClient

client = PiyAPIClient(api_key="sk_live_...")

# 1. Store memory with bitemporal valid_at interval
mem = client.memories.store(
    content="Patient is allergic to penicillin and penicillin-family antibiotics",
    valid_at="2024-01-15T00:00:00Z",
    tags=["medical", "allergies", "critical"],
    user_id="pat_4091"
)

# 2. Pin memory to guarantee 100% recall priority
client.memories.pin(memory_id=mem.id)

# 3. Merge two related memories atomically
merged = client.memories.merge(
    source_ids=[mem.id, "mem_prev_819"],
    summary="Patient has verified life-threatening allergy to all penicillin derivatives"
)

Platform / Retrieval

Hybrid Search & UnifiedScorer (11 Signals)

A multi-signal hybrid search engine combining pgvector HNSW with BM25 via calibrated Reciprocal Rank Fusion.

Search Subsystem
•
UnifiedScorer • 11 Signals • RRF_K=30

PiyAPI eliminates search blindspots by evaluating eleven contextual signals simultaneously:

01
UnifiedScorer (11 Signals in 1 Pass) RRF_K=30
Simultaneously evaluates dense cosine similarity, BM25 trigram text score, recency half-life decay, entity overlap, contradiction penalty, and pin weights.
02
Dense Vector Search (pgvector HNSW) EMBEDDING ENGINE
Indexes 1536-dimensional vectors using Hierarchical Navigable Small World (HNSW) graphs, yielding sub-10ms nearest neighbor recall with 99.2% precision.
03
Sparse BM25 Trigram Search EXACT KEYWORDS
Captures rare entity IDs, acronyms, code identifiers, and email addresses that dense embeddings frequently blur.
04
Configurable Hybrid Alpha Blend SCORING CONTROL
Tune the balance between semantic meaning and exact keyword match using alpha (e.g. alpha=0.7 for 70% vector + 30% BM25).

The 11 Scoring Signals

 Signal Name Evaluation Logic & Mathematical Weight
01 Dense Vector Cosine similarity across 1536-dim embedding space via pgvector HNSW
02 BM25 Trigram Sparse term-frequency / inverse-document-frequency for exact code and identifier recall
03 Recency Half-Life Exponential decay curve: score = score * (0.5 ^ (days_elapsed / half_life))
04 Pin Weight Guaranteed +1.0 priority boost for immutable compliance rules and user constraints
05 Entity Overlap Jaccard similarity on named entity recognition (NER) tokens extracted from query
06 Bitemporal Filter Hard boundary evaluation against valid_at intervals to prevent chronological anachronisms

Python Search Example

Execute a hybrid multi-signal search with custom score thresholding:

search_query.py 
from piyapi_memory import PiyAPIClient

client = PiyAPIClient(api_key="sk_live_...")

# Execute hybrid search with UnifiedScorer
response = client.search(
    query="What AWS region does the customer require for data residency?",
    user_id="usr_8821",
    limit=5,
    min_score=0.35,
    alpha=0.65 # 65% dense vector + 35% BM25
)

for item in response.results:
    print(f"[{item.score:.3f}] {item.content} (Vector: {item.vector_score}, BM25: {item.bm25_score})")

Keep memory strictly scoped across multi-tenant organizations, individual users, and ephemeral sessions.

Identity & Governance
•
Namespace Scoping • HIPAA/GDPR Redaction

PiyAPI ensures that memories belonging to User A can never be observed or recalled by User B:

01
Strict Multi-Tenant Namespace Isolation TENANT SECURITY
Enforce hard boundaries between enterprise customers using the X-Namespace-Prefix header. Data partitions prevent cross-tenant data leakage.
02
3-Tier Identity Hierarchy SCOPING MODEL
Structure memories hierarchically: Organization / Tenant → User ID (usr_...) → Session ID (sess_...).
03
Automated PHI / PII Redaction HIPAA & GDPR
Integrated privacy pipeline automatically detects and tokenizes Social Security Numbers, credit cards, emails, and medical identifiers prior to vector storage.
04
Autonomous Session Mining CONTINUOUS LEARNING
Use POST /api/v1/sessions/mine to automatically extract salient user preferences, goals, and facts from multi-turn chat sessions.

Namespace Scoping in TypeScript

Isolate enterprise tenant partitions with headers:

tenant_scoping.ts 
import { PiyAPIClient } from '@piyapi/sdk';

// Scoped multi-tenant client instance
