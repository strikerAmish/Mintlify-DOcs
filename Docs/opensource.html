Open Source / Overview

Open Source Overview

Run Negentro on your own infrastructure with full control over your data, configuration, and deployment environment.

Open Source Self-hosted Developer Infrastructure

Negentro Open Source gives you the flexibility to run the intelligence infrastructure on your own environment while keeping control over your data and configuration.

Developers can install the SDK directly into an application, or run a self-hosted server as an independent service. Both approaches let you configure storage, embeddings, and model providers to match your existing infrastructure.

The stack is designed to be extended through APIs and integrations, allowing you to connect existing databases, plug in custom model providers, and build workflows that fit your deployment requirements.

Run Negentro your way

As a library
Install the SDK directly into your application for embedded memory without external dependencies.
As a self-hosted server
Run Negentro as an independent service with control over infrastructure, storage, models, and configuration.

const negentro = createNegentro({
  llm: "openai:gpt-4o",

Open Source / Python SDK Quickstart

Python SDK Quickstart

Install and integrate Negentro embedded memory into your Python agents, LLM pipelines, and backend services.

Python SDK Embedded Library

Installation

Install the core Python package via pip. You can also specify optional vector backend dependencies:

Terminal 
# Core embedded package
pip install negentro-memory

# Or install with optional database drivers (pgvector, redis, qdrant)
pip install "negentro-memory[pgvector,redis]"

Quickstart Code

Initialize the memory engine and start storing conversational context in under five lines of code:

quickstart.py 
from negentro import Memory

# 1. Initialize embedded memory
m = Memory()

# 2. Add memories for a specific user
m.add(
    "User prefers dark mode UI and works primarily with React and TypeScript.",
    user_id="usr_9918",
    metadata={"category": "preferences"}
)

# 3. Retrieve relevant context
results = m.search(
    query="What frontend framework does the user like?",
    user_id="usr_9918",
    limit=3
)

for mem in results["results"]:
    print(f"Score: {mem['score']} | Content: {mem['memory']}")

TypeScript Setup & Usage

Initialize the Negentro client to connect to your self-hosted server or local instance:

index.ts 
import { NegentroClient } from '@negentro/sdk';

const client = new NegentroClient({
  baseUrl: process.env.NEGENTRO_HOST || 'http://localhost:8080',
  apiKey: process.env.NEGENTRO_API_KEY
});

async function main() {
  // Store user preference
  const mem = await client.memories.create({
    content: "User prefers Node.js with Fastify over Express.",
    userId: "user_42",
    tags: ["backend", "frameworks"]
  });
  console.log("Created memory ID:", mem.id);

  // Hybrid search across memories
  const results = await client.search({
    query: "What web framework does the user prefer?",
    userId: "user_42",
    limit: 5
  });
  console.log("Top match:", results.results[0]);
}

main();

Next.js & Vercel AI SDK Integration

Assemble token-budgeted prompt context inside a Next.js App Router route handler:

app/api/chat/route.ts 
import { NegentroClient } from '@negentro/sdk';
import { openai } from '@ai-sdk/openai';
import { streamText } from 'ai';

const negentro = new NegentroClient();

export async function POST(req: Request) {
  const { messages, userId } = await req.json();
  const lastMessage = messages[messages.length - 1].content;

  // 1. Retrieve targeted memory context
  const context = await negentro.context.retrieve({
    query: lastMessage,
    userId: userId,
    tokenBudget: 800
  });

  // 2. Stream completion with grounded memory
  return streamText({
    model: openai('gpt-4o'),
    system: `You are a helpful assistant. Context: ${context.assembledPrompt}`,
    messages
  }).toDataStreamResponse();
}

Open Source / Self-hosted Server

Self-hosted Server Deployment

Deploy Negentro as a high-performance, containerized microservice within your own private cloud or on-premise infrastructure.

Docker Kubernetes Self-hosted Microservice

Docker Compose Deployment

Spin up a complete Negentro instance with PostgreSQL (pgvector) and Redis in seconds:

docker-compose.yml 
version: '3.8'

services:
  negentro-server:
    image: negentro/server:latest
    ports:
      - "8080:8080"
    environment:
      - PORT=8080
      - DATABASE_URL=postgresql://negentro:secret@postgres:5432/negentro
      - REDIS_URL=redis://redis:6379
      - OPENAI_API_KEY=${OPENAI_API_KEY}
      - ENABLE_STUDIO=true
    depends_on:
      - postgres
      - redis

  postgres:
    image: pgvector/pgvector:pg16
    environment:
      - POSTGRES_USER=negentro
      - POSTGRES_PASSWORD=secret
      - POSTGRES_DB=negentro
    volumes:
      - pgdata:/var/lib/postgresql/data

  redis:
    image: redis:7-alpine
    volumes:
      - redisdata:/data

volumes:
  pgdata:
  redisdata:

Run the stack with:

Terminal
docker compose up -d
# Negentro API ready at http://localhost:8080
# Web Studio ready at http://localhost:8080/studio

Open Source / Web Studio

Web Studio

A visual administrative interface and debugger for inspecting memories, tuning retrieval parameters, and managing users.

Web Studio Admin UI Visual Debugger

What is Web Studio?

Web Studio is a lightweight, responsive admin dashboard bundled directly into Negentro. It allows engineering teams to visualize what their AI agents are remembering in real-time, test semantic queries, and inspect raw embedding vectors without opening database shells.

Key Capabilities

Memory Explorer
Filter memories by user ID, agent ID, session, or tags. Inspect bitemporal timestamps (valid_at vs system_at) and edit facts directly.
Retrieval Playground
Test live queries with side-by-side comparisons of Dense Vector vs BM25 keyword search. Adjust the alpha slider and observe Reciprocal Rank Fusion scores.
Knowledge Graph Viewer
Interactive 2D/3D visualization of entity nodes and relationships extracted from conversation histories.
Audit & Privacy Redaction
Verify automated PII and PHI redaction rules. Inspect revision histories to understand how conflicting facts were resolved.

Launching Web Studio

If you are running the self-hosted Docker container, navigate directly to http://localhost:8080/studio. Alternatively, run the standalone studio CLI:

Terminal
# Run standalone Web Studio pointing to any Negentro instance
npx @negentro/studio --server http://localhost:8080

Open Source / Configuration

Configuration

Fine-tune every layer of the memory stack — from vector dimensions and chunking strategies to LLM inference pipelines.

Configuration Config Schema Environment Variables

Complete Configuration Schema

Negentro reads configuration from negentro.config.json, a JavaScript/TypeScript config file, or environment variables:

negentro.config.json
{
  "llm": {
    "provider": "openai",
    "model": "gpt-4o",
    "temperature": 0.1
  },
  "embedder": {
    "provider": "openai",
    "model": "text-embedding-3-small",
    "dimension": 1536
  },
  "vector_store": {
    "provider": "pgvector",
    "connection_uri": "postgresql://negentro:secret@localhost:5432/negentro",
    "collection_name": "negentro_memories"
  },
  "storage": {
    "bitemporal_enabled": true,
    "history_store": "postgres"
  },
  "cache": {
    "provider": "redis",
    "url": "redis://localhost:6379",
    "ttl_seconds": 3600
  }
}

Resolution Precedence

Configuration values are resolved in the following priority order:

  1. Direct arguments passed to SDK methods (e.g. user_id, limit).
  2. System environment variables (e.g. OPENAI_API_KEY, DATABASE_URL).
  3. Configuration file (negentro.config.json).
  4. Default production settings.

Open Source / Storage

Storage & Knowledge Graphs

Durable transactional storage for relational memories, bitemporal graphs, session logs, and cache layers.

PostgreSQL SQLite Redis Bitemporal KG

Three-Tier Storage Architecture

1. Relational Tier
→
PostgreSQL or SQLite storing memory revisions, user identifiers, raw conversational inputs, and audit records.
2. Graph Tier
→
PiyGraph tracking real-world facts with separate valid_at and system_at timestamps.
3. Cache Tier
→
Redis storing hot memory buffers, sliding-window rate limit counters, and semantic query caches.

Open Source / Reranking

UnifiedScorer & Reranking

Combine dense semantic similarity, sparse BM25 text match, recency decay, and cross-encoders for precision retrieval.

Reranking UnifiedScorer Reciprocal Rank Fusion BM25

The 3-Stage Reranking Pipeline

Stage 1: Candidates
→
Retrieve Top 50 vectors (HNSW) alongside Top 50 BM25 trigram full-text matches.
Stage 2: Fusion
→
Merge candidates using Reciprocal Rank Fusion (RRF_K=30) to prevent keyword or dense bias.
Stage 3: Scoring
→
UnifiedScorer evaluates 11 weighted signals (similarity, text match, recency decay, contradiction penalty, and pinned weight).

Tuning Retrieval Parameters

rerank_config.py
results = m.search(
    query="User preferences for deployment target",
    user_id="usr_9918",
    alpha=0.7,             # 0.7 Vector weight / 0.3 BM25 text weight
    min_score=0.25,         # Rejects low-confidence matches
    recency_decay_days=30  # Half-life for temporal fading
)
