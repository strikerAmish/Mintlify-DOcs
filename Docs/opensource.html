Open Source Self-hosted Developer Infrastructure

PiyAPI Open Source provides the flexibility to deploy our cognitive memory engine entirely within your VPC. Maintain strict data privacy, enterprise compliance, and total configuration control without sacrificing the power of bitemporal reasoning.

Developers can install the SDK directly into an application as a lightweight library, or run the full PiyAPI server as an independent, scalable microservice. Both approaches allow you to configure storage, embeddings, and BYOK (Bring Your Own Key) model routing to match your existing infrastructure.

The stack is designed to be fully extensible—connect your existing PostgreSQL databases, plug in custom LLMs, and build active inference workflows tailored to your exact deployment constraints.

Configure your stack

Explicitly declare infrastructure backends in a single declarative configuration file:

piyapi.config.ts 
import { createPiyAPI } from '@piyapi/sdk';

const piyapi = createPiyAPI({
  llm: "openai:gpt-4o",
  embeddings: "openai:text-embedding-3-small",
  // Connect directly to your existing infrastructure
  vectorStore: "pgvector://localhost:5432/piyapi",
  storage: "postgres://localhost:5432/piyapi_graph",
  cache: "redis://localhost:6379"

Installation

# Or install with optional database drivers (pgvector, redis, qdrant)

Quickstart Code

Initialize the memory engine and start storing conversational context in under five lines of code:

quickstart.py 
from piyapi import Memory

# 1. Initialize embedded memory
m = Memory()

# 2. Add memories for a specific user
m.add(
    "User prefers dark mode UI and works primarily with React and TypeScript.",
    user_id="usr_9918",
    metadata={"category": "preferences"}
)

# 3. Retrieve relevant context
results = m.search(
    query="What frontend framework does the user like?",
    user_id="usr_9918",
    limit=3
)

for mem in results["results"]:
    print(f"Score: {mem['score']} | Content: {mem['memory']}")

LangChain & CrewAI Integration

Use PiyAPI as the persistent memory provider for popular agent orchestration frameworks:

langchain_agent.py 
from langchain_openai import ChatOpenAI
from piyapi.integrations.langchain import PiyAPIMemory

# Plug PiyAPI directly into LangChain agents
memory = PiyAPIMemory(user_id="alex_204")
llm = ChatOpenAI(model="gpt-4o")

# Memory automatically syncs after each conversational turn
context = memory.load_memory_variables({"prompt": "What did we discuss earlier?"})
crewai_agent.py 
from crewai import Agent
from piyapi.integrations.crewai import PiyAPICrewMemory

# Persistent memory across multiple CrewAI agents
crew_memory = PiyAPICrewMemory(namespace="crew_research_team")

researcher = Agent(
    role="Senior Analyst",
    goal="Synthesize company filings with user-defined constraints",
    memory=crew_memory,
    verbose=True
)
💡
Automatic sync: When using the LangChain or CrewAI integrations, memory extractions occur asynchronously in background worker threads, preventing latency spikes on user-facing response streams.

TypeScript Setup & Usage

Initialize the PiyAPI client to connect to your self-hosted server or local instance:

index.ts 
import { PiyAPIClient } from '@piyapi/sdk';

const client = new PiyAPIClient({
  baseUrl: process.env.PIYAPI_HOST || 'http://localhost:8080',
  apiKey: process.env.PIYAPI_API_KEY
});

async function main() {
  // 1. Store user preference
  const mem = await client.memories.create({
    content: "User prefers Node.js with Fastify over Express.",
    userId: "user_42",
    tags: ["backend", "frameworks"]
  });
  console.log("Created memory ID:", mem.id);

  // 2. Hybrid search across memories
  const results = await client.search({
    query: "What web framework does the user prefer?",
    userId: "user_42",
    limit: 5
  });
  console.log("Top match:", results.results[0]);
}

main();

Next.js & Vercel AI SDK Integration

Assemble token-budgeted prompt context inside a Next.js App Router route handler with streaming response support:

app/api/chat/route.ts 
import { PiyAPIClient } from '@piyapi/sdk';
import { openai } from '@ai-sdk/openai';
import { streamText } from 'ai';

const piyapi = new PiyAPIClient();

export async function POST(req: Request) {
  const { messages, userId } = await req.json();
  const lastMessage = messages[messages.length - 1].content;

  // 1. Retrieve targeted memory context respecting strict token limits
  const context = await piyapi.context.retrieve({
    query: lastMessage,
    userId: userId,
    tokenBudget: 800
  });

  // 2. Stream completion with grounded memory injection
  return streamText({
    model: openai('gpt-4o'),
    system: `You are a helpful assistant. Context: ${context.assembledPrompt}`,
    messages
  }).toDataStreamResponse();
}
ⓘ
Token Budget Precision: The context.retrieve() method evaluates token counts using exact tiktoken encodings to prevent model context window overflow while prioritizing high-signal memories.

Docker Compose Deployment

Spin up a complete PiyAPI instance with PostgreSQL (pgvector) and Redis in seconds:

docker-compose.yml 
version: '3.8'

services:
  piyapi-server:
    image: piyapi/server:latest
    ports:
      - "8080:8080"
    environment:
      - PORT=8080
      - DATABASE_URL=postgresql://piyapi:secret@postgres:5432/piyapi
      - REDIS_URL=redis://redis:6379
      - OPENAI_API_KEY=${OPENAI_API_KEY}
      - ENABLE_STUDIO=true
    depends_on:
      - postgres
      - redis

  postgres:
    image: pgvector/pgvector:pg16
    environment:
      - POSTGRES_USER=piyapi
      - POSTGRES_PASSWORD=secret
      - POSTGRES_DB=piyapi
    volumes:
      - pgdata:/var/lib/postgresql/data

  redis:
    image: redis:7-alpine
    volumes:
      - redisdata:/data

volumes:
  pgdata:
  redisdata:

What is Web Studio?

Web Studio is a lightweight, responsive admin dashboard bundled directly into PiyAPI. It allows engineering teams to visualize what their AI agents are remembering in real-time, test semantic queries, and inspect raw embedding vectors without opening database shells.

Key Capabilities

Memory Explorer
Filter memories by user ID, agent ID, session, or arbitrary tags. Inspect bitemporal timestamps (valid_at vs system_at) and edit facts directly.
Bitemporal Fact Inspector
Retrieval Playground
Test live queries with side-by-side comparisons of Dense Vector vs BM25 keyword search. Adjust the alpha slider and observe Reciprocal Rank Fusion scores in real time.
RRF_K=30 11 Signals
Knowledge Graph Viewer
Interactive 2D/3D force-directed visualization of entity nodes and relationships extracted automatically from conversational interaction histories.
PiyGraph Entity Graph
Audit & Privacy Redaction
Verify automated PII and PHI redaction rules. Inspect revision histories to understand exactly how contradictory facts were resolved across time.

Resolution Precedence

Configuration values are resolved dynamically in descending priority order:

1
Direct Method Arguments (Highest Priority)
Values passed directly during function calls (e.g. user_id="usr_99", limit=10, threshold=0.85).
2
System Environment Variables
Standard system env vars (e.g. OPENAI_API_KEY, DATABASE_URL, REDIS_URL).
3
Configuration File
Declared static configurations from piyapi.config.json or piyapi.config.ts in the root directory.
4
Production Sane Defaults (Fallback)
Default enterprise settings: pgvector store, HNSW indexing, text-embedding-3-small, and gpt-4o.

Configuring pgvector

PostgreSQL with pgvector is the recommended open-source vector store because memories, embeddings, and temporal revision graphs share a single atomic database pass:

pgvector_init.sql 
-- Enable the vector extension
CREATE EXTENSION IF NOT EXISTS vector;

-- Optimized HNSW vector index for cosine distance
CREATE INDEX idx_memories_embedding_hnsw 
ON memories 
USING hnsw (embedding vector_cosine_ops)
WITH (m = 16, ef_construction = 64);

Three-Tier Storage Architecture

PiyAPI isolates state across three dedicated tiers to balance sub-10ms latency with transactional integrity:

01
1. Relational Tier (PostgreSQL) ACID Storage
Stores raw memory records, tenant metadata, foreign key constraints, and user identity mappings. Transactional consistency guarantees zero state corruption.
02
2. Temporal Graph Tier (PiyGraph) Bitemporal
PiyGraph tracks real-world validity (valid_at) separately from system audit timestamps (system_at). Answers time-travel queries like "What did our agent know on March 12?"
03
3. Cache Tier (Redis Cluster) In-Memory
Redis stores hot memory query buffers, sliding-window rate limit counters, distributed locks, and semantic query caches for instant p95 retrieval.

Filtered Search Example

Combine semantic natural language queries with deterministic JSON metadata filters:

search_filtered.py 
results = m.search(
    query="What are our database credentials?",
    user_id="dev_lead",
    filters={
        "$and": [
            {"environment": {"$eq": "production"}},
            {"service": {"$in": ["postgres", "redis"]}},
            {"archived": {"$ne": True}}
        ]
    },
    limit=5
)

UnifiedScorer & Reranking

Combine dense semantic similarity, sparse BM25 text match, recency decay, and cross-encoders for precision retrieval.

UnifiedScorer Engine
•
11 Signals • Reciprocal Rank Fusion RRF_K=30
Reranking UnifiedScorer Reciprocal Rank Fusion BM25

The 3-Stage Reranking Pipeline

01
Stage 1: Multi-Index Candidate Generation Dual Retrieval
Retrieve the Top 50 vectors via PostgreSQL pgvector HNSW alongside the Top 50 BM25 trigram full-text keyword matches in a single parallelized query.
02
Stage 2: Reciprocal Rank Fusion (RRF) RRF_K=30
Fuse and normalize candidate rank scores using score = Σ 1 / (30 + rank_i) to prevent bias toward dense vectors or sparse keyword matches.
03
Stage 3: UnifiedScorer 11-Signal Pass Precision Filter
UnifiedScorer applies 11 weighted signals: semantic similarity, exact phrase matches, exponential recency decay, contradiction penalties, and pinned boosts.

Tuning Retrieval Parameters

Fine-tune weights and decay constants to fit conversational or factual agent tasks:

tuning_config.ts 
const searchConfig = {
  rrf_k: 30,                // Lower k boosts top ranks (default: 30)
  dense_weight: 0.65,        // Weight for semantic cosine similarity
  sparse_weight: 0.35,       // Weight for BM25 keyword matching
  decay_half_life_days: 14,  // Recency decay half-life in days
  pinned_boost: 1.5          // Multiplier for explicitly pinned memories
};

Ingesting Image Memories

Pass raw images via base64 or remote URL — the engine extracts visual OCR text and generates dense visual representations:

multimodal_ingest.py 
from piyapi import Memory

m = Memory()

# Ingest an architecture diagram
m.add(
    "https://example.com/system-architecture.png",
    user_id="lead_architect",
    modality="image",
    metadata={"project": "v2_migration"}
)

# Retrieve by semantic description
results = m.search(
    query="Where is the Redis cache located in the architecture diagram?",
    user_id="lead_architect"
)
